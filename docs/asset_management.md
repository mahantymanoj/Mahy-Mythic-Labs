# 📦 Asset Management

> **Mahy Mythic Labs Asset Management**
>
> Version: 1.0
>
> This document defines the standards, lifecycle, organization, naming conventions, storage strategy, and governance for all assets used and generated by Mahy Mythic Labs.

---

# 1. Purpose

The Asset Management system ensures that every project asset is:

- Organized
- Reusable
- Traceable
- Versioned
- Licensed
- Easy to locate
- Safe to archive

The goal is to support scalable AI-assisted production without creating duplicate or orphaned assets.

---

# 2. Asset Categories

Assets are divided into two major groups.

## Source Assets

Source assets are manually created or licensed and are shared across multiple episodes.

Examples:

- Logos
- Fonts
- Brand graphics
- Licensed music
- Licensed sound effects
- Reference images
- Character reference sheets
- Environment reference sheets

These assets are stored under the shared `assets/` directory.

---

## Generated Assets

Generated assets are created specifically for an episode.

Examples:

- AI-generated images
- AI-generated videos
- Narration
- Temporary renders
- Intermediate exports
- Motion graphics

Generated assets should remain inside the corresponding project directory whenever practical.

# 4. Asset Lifecycle

Every asset follows the same lifecycle.

```
Request

↓

Generate

↓

Review

↓

Approve

↓

Use

↓

Archive

↓

Reuse
```

Assets should never bypass the review stage.

# 6. Naming Convention

Use descriptive, lowercase, snake_case filenames.

Examples:

```
earth_from_orbit.png

galaxy_zoom.mp4

intro_narration.wav

episode_metadata.json
```

Avoid:

```
image1.png

final_final.mp4

newfile.wav

test123.jpg
```

---

# 7. Directory Rules

Shared assets belong only in:

```
assets/
```

Episode assets belong only in:

```
projects/<episode>/
```

Do not mix reusable assets with generated outputs.

---

# 8. Asset Metadata

Every generated asset should have associated metadata when appropriate.

Example:

```
asset_name

generation_date

generator

prompt_version

provider

model

license

episode

revision
```

Metadata improves reproducibility and auditing.

---

# 9. Versioning

Assets should be versioned only when meaningful changes occur.

Example:

```
thumbnail_v1.png

thumbnail_v2.png

thumbnail_final.png
```

Avoid unnecessary version proliferation.

---

# 10. Approval Workflow

Every generated asset passes through the following stages:

```
Generated

↓

Pending Review

↓

Approved

↓

Rejected

↓

Archived
```

Only approved assets should be included in published videos.

---

# 11. Character Library

Reusable characters should maintain visual consistency.

Each character should include:

- Name
- Description
- Reference images
- Prompt reference
- Style notes

Characters are stored in:

```
assets/characters/
```

---

# 12. Environment Library

Reusable environments should include:

- Name
- Description
- Lighting style
- Camera style
- Reference images
- Prompt references

Stored in:

```
assets/environments/
```

---

# 13. Branding Assets

Branding assets include:

- Logo
- Intro
- Outro
- Lower thirds
- Watermarks
- Icons

Stored in:

```
assets/branding/
```

These assets should be updated only through approved branding revisions.

---

# 14. Reference Assets

Reference assets support research and visual consistency.

Examples:

- Historical artwork
- Architecture
- Space imagery
- Scientific diagrams

Reference assets should never be redistributed unless licensing permits.

---

# 15. Licensing

Every third-party asset must include:

- Source
- License type
- Author
- Date obtained
- Usage restrictions

License information should be stored under:

```
assets/licenses/
```

No unlicensed content should be used in production.

---

# 16. Archive Policy

Unused or superseded assets should be archived rather than deleted.

Archive structure:

```
archive/

2026/

EP001/

images/

videos/
```

Archived assets remain available for future reference.

---

# 17. Backup Strategy

Recommended backups:

- Repository
- Episode projects
- Approved assets
- Licensed assets
- Production Bible
- Knowledge Base

Backups should be automated where possible.

---

# 18. Quality Standards

Every asset should satisfy:

- High resolution
- Consistent style
- Correct aspect ratio
- Appropriate color grading
- No visible artifacts
- Brand consistency

Assets failing quality review should be regenerated or rejected.

---

# 21. Summary

Mahy Mythic Labs treats assets as long-term production resources rather than temporary files. By separating reusable source assets from episode-specific generated outputs, enforcing naming conventions, maintaining metadata, and tracking licensing, the project ensures that assets remain organized, reusable, and scalable as the content library grows.
