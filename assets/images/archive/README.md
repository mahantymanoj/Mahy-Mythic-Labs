# Archived Images

## Purpose

This folder stores rejected, superseded, outdated, or retired image assets for traceability.

## Archive Reasons

| Reason | Meaning |
| --- | --- |
| Rejected | Did not meet quality, accuracy, or style standards |
| Superseded | Replaced by a newer approved version |
| Unused | Generated but not selected for production |
| Rights restricted | Cannot be used commercially or publicly |
| Historical issue | Contains anachronism or unsupported reconstruction |
| Technical issue | Contains visual artifacts, incorrect anatomy, or poor composition |

## Retention Policy

Archived images must be kept for the full duration of the project they belong to, plus a minimum of 12 months after final publication. This ensures prompt records, review history, and generation lineage remain available for audit, reuse consideration, and reference.

After this period, images may be permanently deleted only if confirmed as non-essential to any active or planned production.

## Recovery Process

An archived image can be re-reviewed and potentially returned to `../approved/` by following these steps:

1. Identify the archived image and locate its original prompt and review notes.
2. Submit it for a new review covering quality, accuracy, rights, and style.
3. If it passes review, move it to `../approved/` with a new version number.
4. Update the asset register status from `Archived` to `Approved`.
5. Document the recovery reason and date in the asset register Notes field.

## File Naming

Retain the original filename and add an archive suffix:

`[original-file-name]-archived-[reason]-v##.[extension]`

Example:

`ep001-antikythera-gear-closeup-archived-artifact-v01.png`

## Rules

- Do not permanently delete assets without confirming they are not needed for audit, reuse, or prompt reference.
- Keep original prompt and review notes where available.
- Archived assets must never be used in final exports unless formally re-reviewed and re-approved.
